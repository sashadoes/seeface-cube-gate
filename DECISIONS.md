# Decisions

Choices made without asking, per the brief ("make a sensible choice, note it, keep going").

1. **New route `/world/`, not a refactor of `/labyrinth`** (2026-10-09). The three-button rule can't coexist with the live labyrinth's HUD, and other sessions are shipping on it. Shared: `analytics.ts` only.
2. **Worktree `seeface-world-core`, branch `feature/world-core-v1` off `main`.** The main checkout has another session's uncommitted coffee-campaign work.
3. **Plain three.js, no React Three Fiber.** It meets the budget, and the team already knows it. React renders only the three buttons and overlays.
4. **Server in TypeScript run directly by Node ≥ 23.6 (type stripping).** There's no build step, and the server shares `shared/world/*.ts` with the client. Rule: erasable syntax only (no enums, no parameter properties, no namespaces). This is enforced by `erasableSyntaxOnly`.
5. **Our own WebSocket server instead of the public MQTT relay.** The spec requires the server to be authoritative for coins, rooms, permissions and moderation. A public relay can't be.
6. **Voice: a `VoiceAdapter`, mesh first.** Development never blocks on a LiveKit account (see 19 for LiveKit's status: the client always uses mesh today, even when the server has LiveKit keys). Mesh signalling goes only through our server, and only between members of the same room (or proximity group) who have passed the age gate.
7. **Age gate: the mock adapter is refused in production.** Self-declaration isn't "highly effective age assurance". Without a vendor, production voice stays locked and the world says why. This is stricter than `feature/voice-rooms` (self-declared sheet) on purpose.
8. **The AI host is labelled "AI" (spec section 7).** This overrides the 2026-10-07 `/labyrinth` rule "never show the word ai". The newer brief explicitly requires the label. That older rule still applies to `/labyrinth`.
9. **When no human is online, nothing is faked.** The busiest room is chosen from real counts. With zero people, the player drops into the host's room, which reads "quiet right now · 0 listening". The AI host speaks only as a labelled AI.
10. **Speech-to-text has no "free" fallback.** The browser Web Speech API sends audio to Google on Chrome, and we can't promise what happens to it. So the mock STT produces nothing. Transcripts only exist once a configured provider and an opted-in speaker are both present.
11. **Coins earned by voice need a real listener.** "Speaking" pays only while at least one other human is in the room, and it's capped per day. This stops people farming coins by talking to an empty room.
12. **No Rapier, no physics engine.** Rapier's WASM (~1.4 MB) would take a big bite of the 5 MB budget for a handful of balls. Kick balls are simulated locally with grid collision and drift home after 8 s, so everyone's room converges without server physics. They aren't synced live; that's documented as a known issue.
13. **The "slide down into the music district" toy isn't built.** The world is one floor level. Wells are the vertical move, and a slide needs a second level. Bounce pads, wind vents, speed strips, low-g corridors (the Dream Garden) and secret walls are built.
14. **Big public rooms with no human host auto-queue raised hands.** The spec says the host taps to bring people up. Curated rooms have no human host (the AI host can't moderate the stage), so raised hands get free seats in order, and silent speakers yield after 3 min when hands are waiting. Owners, hosts and moderators use "bring up" on the avatar card.
15. **Gifts sit in the text/reaction sheet, not on the avatar card.** The spec says the card is "Follow · Mute · Report · Block. That's all." Gifts go to whoever is speaking (the loudest voice in your room), which is also who the spec says gifts are for.
16. **The AI host speaks as text, not with a synthetic voice.** Its lines appear labelled "AI host" to people in that room. A synthetic voice in a voice-first room is easy to mistake for a person, so it waits for Sasha's call.
17. **The host model is `claude-opus-5-5`** (low effort for lines and tags, medium for verdicts) with server-side refusal fallbacks and a daily call cap (`HOST_DAILY_CAP`). That matches the existing NPC code. `HOST_MODEL` can switch it.
18. **Streaming speech-to-text is an interface with a no-op mock.** Wiring a real provider without a chosen vendor and key would be guesswork, and inventing captions is off the table. The whole transcript → verdict → approval pipeline is tested with captions fed in directly.
19. **LiveKit: server token minting only.** The client LiveKit adapter isn't built yet. Mesh voice works today up to about 8 talkers per room; LiveKit is next for bigger rooms.
20. **Text bubbles also need the 18+ check.** The world is 18+ at launch, and bubbles are stranger-to-stranger chat too.
21. **"Delete my data" anonymises ledger rows instead of deleting them.** Purchase records must still add up. The user id on those rows becomes "deleted", and everything personal (profile, transcript lines, quotes, follows, reports they filed) is removed.
22. **Gifts and room purchases happen only in the world UI, never by URL or HTTP.** Every coin movement is a WebSocket intent the server validates against the ledger. The only HTTP coin writes are the Stripe webhook (signature verified) and the dev-only mock completion.
